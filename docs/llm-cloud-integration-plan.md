# 云端 LLM 集成立项草案

> 后续决策更新：用户改为局域网 Qwen 工作室 API，只部署一个模型（14B/30B 二选一）；
> 分析员、复核员和审查员是同模型的三个独立角色，默认串行，而非独立模型交叉验证。
> 连接测试、Markdown 快照/预览和单章三角色闭环已实现。核心业务位于独立的“小说分析”第三页，
> 见 [LLM 工作台](llm-workbench.md) 和 [小说分析](novel-analysis.md)；原云端方案保留作历史草案。
> 下文保留原云端草案作为历史设计参考，实际部署、HTTP 授权与密钥规则以工作台说明为准。

状态：后端方向已确认（云端模型 API）；首期范围与阶段待用户确认。
本文件是规划，不代表功能已经实现。立项期间不调用云端、不发送小说原文。

## 1. 项目目标

把已有的 LLM、上下文和结构化分析基础模块接入桌面应用，形成一个可用、
可取消、可追溯的 **当前章节分析闭环**：

配置云端模型 → 测试连接 → 预览发送内容 → 分析当前章 → 校验证据 → 查看和保存结果。

首期成果以真实 GUI 操作为准，不以“库编译成功”或“模拟响应通过”为完成。
现有 Markdown 导入、阅读、双字数统计和 Reader 优先布局必须保持可用。

## 2. 已有基础与缺口

| 已有模块 | 可复用能力 | 本轮需要接入或补齐 |
| --- | --- | --- |
| `ILLMClient` / `QwenClient` | 异步请求、队列、取消、超时、有限重试、结构化响应 | GUI 配置、云端服务能力探测、调用编排 |
| `ContextEngine` / Context Inspector | 有预算的提示词、先存快照再生成请求、内容检查 | 当前 Markdown 章的原文快照、任务提示词版本 |
| `ChapterAnalyzer` | 人物、别名、地点、事件、摘要、重要事实、未完线索；严格证据校验 | 实际模型输出到领域结构的适配与结果展示 |
| `LLMRunRepository` / `InferenceRepository` | 请求生命周期、原始载荷、提示词和 schema 版本 | 原文快照关联、领域校验回执、GUI 历史记录 |
| `DialogueExtractor` / Story Memory / 回归模块 | 对话分段、故事状态、离线质量门禁 | 留作后续扩展；首期不默认执行 |

当前 GUI 没有模型设置、测试连接、分析按钮或生产调用链。
现有单元测试证明基础契约，不等于某个云端模型已经通过实测验收。

## 3. 首期范围

### 做什么

- 一个激活的云端连接配置，可指定完整请求地址、模型名和 API Key。
- 测试连接及结构化输出能力，测试只使用内置原创短样本。
- 用户主动选择“分析当前章”，不随导入、打开项目或切换章节自动调用。
- 展示人物、别名、地点、事件、摘要、重要事实及未完线索。
- 对模型结论展示原文证据、推断标识和置信度；置信度是模型声明，不是校准概率。
- 展示进度阶段、错误原因、耗时和服务实际返回的 token 用量。
- 支持取消、手动重试、重新打开项目后查看历史结果。

### 暂不做什么

- 批量分析 743 章、自动后台扫描、同时调用多个模型。
- 自动改写 Markdown、自动提交小说、自动发布 GitHub PR。
- 自动把模型结论写入跨章 Story Memory，或把“推测”升级成“事实”。
- 全书一致性检查、自动对话分段和自动校对；这些作为后续独立任务接入。
- 本地模型部署、模型下载、RAG/向量数据库、训练或微调。
- 自动回退到另一家云端、无限重试、静默截断章节。
- 首期流式文本显示；先保证完整结构化结果的校验和持久化。

## 4. 交互与隐私边界

### 模型设置

建议入口为 `Settings > 模型设置`，主界面工具栏提供“分析当前章”和“取消”。
设置对话框首屏只放服务名称、完整 API 请求地址、模型名、密钥和测试按钮。
超时、上下文预算、输出预算、结构化模式及重试设置放在折叠的高级选项中。
地址是完整请求地址，不混用基础 URL，不自动重复拼接路径。

云端只允许 HTTPS，正常校验证书，不跳过 TLS 错误；禁止跨服务重定向携带凭据。
具体供应商、API 地址和模型尚未选定，不能假定所有“兼容 API”行为一致。
服务列表接口能返回模型名称，不等于该模型支持本任务的结构化输出。

### 正文发送前

发送确认页显示目标域名、模型、章节与源文件、发送内容预览、token 估算和预算。
默认只发送当前章及必要的任务说明；首期不拼接全书或未分析的前文章节。
连接测试不读取当前小说。用户选择云端后端，不等于同意自动上传全部原文。

用户主动确认分析才能发送正文。切换目标服务时重新确认，不能静默改目的地。
云端的留存政策、地域和版权使用条件须由用户确认；本项目不能承诺供应商不留存。
用户对正文的云端使用权限与 Git 仓库权限是两条不同边界。

非秘密配置可保存在用户级设置中；密钥首期支持会话内输入或显式指定环境变量。
跨重启“记住密钥”只有接入系统凭据存储后才启用，不用普通 QSettings 明文保存。
不把密钥写进 `.loreforge`、源码、提示词、运行快照、报错或 Git。
原文、模型输出和请求快照仅保存在本地项目内，不进入公开测试夹具或 GitHub。
普通日志只记录运行 ID、阶段和脱敏错误，不记录完整载荷；错误响应也需防止泄露密钥。

### 结果界面

新增可折叠的“章节分析”面板，包含摘要、人物、地点、事件、事实/线索、证据及运行记录。
默认不挤占 Reader；分析时或用户主动打开时才显示，保留当前阅读位置。
点击证据可以定位阅读段落，同时展示从原始文件快照切出的准确引文。
结果明确标注“模型分析，未经人工确认”，不会覆盖书籍作者等原有元数据。

## 5. 数据与技术方案

以下新名称为拟新增组件，不是当前已存在的实现。

- `CloudModelProfile`：非秘密连接配置、能力选项、预算与超时；不持有持久化明文密钥。
- `ModelSettingsDialog`：配置、输入检查、脱敏显示和短样本连接测试。
- `ChapterSourceSnapshotAdapter`：从导入项目定位当前源文件，形成不可变的字节快照。
- `ChapterAnalysisController`：生产用例编排和任务状态；不把业务流程堆进 `MainWindow`。
- `ChapterAnalysisWidget`：结果、证据、历史和失败诊断。
- 原文快照与领域校验回执的存储接口：补齐现有推理快照未覆盖的章节来源关系。

### 5.1 原文与偏移不能混用

Markdown 项目的 `sourceHash` 是目录 manifest 的 hash，不是 `01/001.md` 的文件 hash。
Reader 的文字也不是完整源文件：标题标记被去除，空行和 front matter 未完整保存。
因此不能拼接 `Block.text` 冒充原文件，更不能用字符串下标冒充 UTF-8 字节偏移。

发送前校验当前目录版本是否与导入快照一致，安全解析相对路径，拒绝越界及外部链接。
首期发现导入后原文发生变化时，阻止任务并要求重新导入或后续显式刷新，不能混用新旧版本。
保存目录版本 hash、文件 hash、章节切片 hash、原始字节、章节 ID、源文件 ID 和绝对字节范围。
文件已移动、缺失或无法校验时明确报错，不自动搜索磁盘或分析缓存显示文字。

请求和校验都绑定这一份不可变快照。回包时再次检查来源与任务版本；过时结果保留为历史，
但不覆盖当前章的有效分析。重启后的证据查看以保存的快照为准，不把已变化的文件冒充旧原文。
保存这些数据需要版本化数据库迁移；原有 schema v6 项目和导入数据必须保留并验证升级路径。

### 5.2 模型证据采用可验证锚点

不把“让模型准确计算中文 UTF-8 字节偏移”作为首期成功前提。
建议给当前章正文块分配快照内锚点，模型返回“块 ID + 原文短引文”。
版本化的适配器在该块原始字节中做精确、唯一匹配，确定真实 `SourceSpan`，
再转换成 `ChapterAnalyzer` 所需的字节证据结构，复用现有严格校验器。

找不到、重复匹配、越界、擅改引文都算证据失败；不模糊搜索、不猜位置、不用相似句替代。
长章超出预算则停止并解释，首期不静默删段；分块合并作为后续单独设计。
推断可无证据，但必须显式标为推断，不能转成有来源的直接事实。

模型侧输出 schema、适配器版本和领域 schema 分别记录，不篡改“原始模型输出”来冒充成功。
若以真实样本证明精确锚点仍不可行，需要调整方案并复验，不能只降低证据门槛。

### 5.3 请求、验证与保存

先保存原文、提示词、schema 和 ContextSnapshot，再通过
`ContextEngine::requestFromStoredSnapshot` 构造生产请求，经 `ILLMClient` 发出。
复用现有网络队列，不在 GUI 线程执行同步等待或大规模读写校验。
当前任务所有文件读取、校验和数据库操作须明确线程归属；Qt SQL 连接不能跨线程混用。

回包依次通过：响应解析 → 模型侧 schema → 锚点转换 → 领域/证据校验 → 版本检查 → 保存。
“HTTP 200”“JSON 可解析”“领域校验成功”是三个不同状态。
`InferenceRepository` 现有验证状态主要覆盖 JSON schema，不能代替领域证据校验。
新增持久化领域回执，记录转换产物、校验错误、适配版本及来源；两层状态均可查看。
只有整个任务校验并保存成功才在 UI 标记完成，重启后仍能核验这些回执。

首期用无前文的章内分析，不读取未来章节、不使用模型聊天历史作为 Story Memory。
为 ContextEngine 准备合法的空 Story State；不构造虚假的跨章记忆。
有效推理记录和分析回执需原子提交；现有仓库事务不支持直接任意嵌套，事务边界需单独设计。
存储失败不得显示“已保存”，失败的原始响应可供本地诊断，但不能作为有效章分析。

### 5.4 云端兼容性和费用控制

复用 `QwenClient` 的现有协议和队列，按供应商能力做小范围适配，不承诺通用兼容。
优先探测严格结构化模式；不支持时，用户明确选择可用 JSON 模式，领域验证仍必须执行。
token 参数名、结构化设置、响应内容及 reasoning 字段需实际测试，不硬编码“所有服务一致”。
思考内容与最终 JSON 分开处理并留痕；不靠随意删除字符把截断或畸形响应改成有效结果。

默认一次只执行一个正文任务，默认不自动重发正文；手动重试创建新的运行记录。
超时、取消或网络断开不能保证云端停止计算，也不能保证供应商不计费，UI 要明确说明。
输出截断、预算不足、鉴权失败、限流、服务错误、无效 JSON 和证据失败分别显示。
估算 token 不是计费 token；服务未提供 usage 时显示“未提供”，不把缺失数据伪装成 0。
首期不显示未经供应商价格确认的货币费用，也不自动更换服务或模型。

### 5.5 状态与生命周期

UI 阶段：准备 → 等待/请求中 → 校验 → 保存 → 完成；另有失败、取消和结果过时。
保留现有运行记录的生命周期枚举，细分 UI 阶段不直接冒充新增数据库状态。
模型配置、源快照、上下文、提示词和 schema 一旦开始任务就冻结，不随界面设置变化。
重复点击不能产生重复的同章并发；切换章节不能把旧章结果写到新章。
打开另一个项目或关闭窗口时取消/结束当前任务，安全处理晚到的回调与数据库资源。
应用异常退出后的未完成记录在下次打开时标为中断，不能自动补发有费用的云端请求。

## 6. 实施阶段

每阶段独立提交、测试和演示；用户确认本立项范围后，从 LLM-1 开始编码。

| 阶段 | 交付物 | 通过标准 |
| --- | --- | --- |
| LLM-1 配置与连接 | 模型设置对话框、会话密钥、短样本测试、能力/预算设置 | 能识别鉴权/网络/TLS/能力错误；无项目也能测试；不发送小说 |
| LLM-2 原文与上下文 | Markdown 快照适配、来源关联及迁移、提示词/schema 版本、发送预览 | 中文/BOM/CRLF/重复引文映射可验证；变更源文件会被拦截；上下文不越预算 |
| LLM-3 单章任务闭环 | Controller、云端请求、精确证据适配、领域校验、任务持久化 | 原创单章实测完成；界面不冻结；取消/失败/过时结果不能写成成功 |
| LLM-4 结果和证据 UI | 分析面板、原文定位、错误诊断、历史查看 | 阅读位置保留；结论与证据可检查；重启后能恢复，不能串章/串项目 |
| LLM-5 验收与交付 | 脱敏回归、真实后端验收、部署验证、使用说明 | 新旧测试通过；Debug/Release 构建及离线部署通过；用户确认单章闭环可用 |

LLM-3 使用实际 API 测试时必须先由用户提供配置并主动触发；CI 只跑本地模拟服务和原创夹具。
真实小说验收需要单独确认云端发送权限，不能把本地读取授权当作云端上传授权。

## 7. 验收清单

- GUI 全程可用：配置、测试、预览、分析、取消、查看、重开项目。
- 原创夹具：人物/别名、地点、事件、摘要、事实与线索；明确区分证据和推断。
- 偏移：中文、扩展汉字、BOM、CRLF、Markdown 标题、重复引文；证据原文与快照一致。
- 异常：401/403、429、5xx、超时、断网、TLS 错误、不支持参数、截断及畸形 JSON。
- 生命周期：切章、换项目、换模型、修改源文件、关闭窗口、中断恢复、数据库写入失败。
- 安全：没有 API Key/原文普通日志泄露；没有自动云端回退；没有正文自动重发。
- 质量：API 成功不等于分析正确。使用既有回归模块检查实际捕获的输出，不复制答案作预测。
  正式质量阈值和供应商/模型版本在原创样本试验后确定，不预先宣称零幻觉。
- 部署：Qt Network、TLS 后端、SQLite 与平台插件齐全，在去掉开发环境 PATH 后验证。
