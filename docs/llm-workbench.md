# LLM 工作台：连接与运行管理

## 已实现

- 主窗口分为“阅读工作台”“LLM 工作台”“小说分析”三个标签页，切页保留阅读状态。
- LLM 页隐藏阅读用的 Context Inspector / Repair Queue，返回阅读页恢复原来的显隐状态。
- 同一个模型规模选择：14B 或 30B。分析员、复核员、审查员为同模型的三个角色，默认串行。
- 完整 API 地址、实际 model ID、会话 API Key，以及局域网免鉴权测试。
- 非秘密配置保存、取消测试、超时、输出参数名选择、text / json_object / json_schema 短样本测试。
- 显示本次响应耗时、服务报告的 token、会话内连接测试累计和脱敏结果日志。

本页仅管理连接和运行统计；**当前章快照/发送预览、三角色状态、分析结果和历史**已迁移到
独立的“小说分析”页，详见 [单章分析闭环](novel-analysis.md)。本页的连接测试仍不发送小说。
“测试通过”不代表模型已通过完整结构化分析或证据校验。

## 使用

1. 进入 LLM 工作台，填写工作室实际部署的完整 Chat Completions 地址。
2. 选择 14B/30B，另行填写服务端实际 model ID；规模选择不自动加载/切换服务端模型。
3. 免鉴权的局域网服务可留空密钥。若使用 HTTP，须主动勾选明文传输授权。
4. 点击“测试连接（内置短样本）”；不会读取当前章节。
5. 若基础调用通过，在高级选项中选择 JSON 模式，验证服务实际支持的结构化能力。
   兼容服务可能需要 `max_tokens` 而非 `max_completion_tokens`，由用户明确选择，不静默回退。

地址须为完整 http/https 请求 URL；不接受 URL 凭据、查询参数或片段，不重复拼接路径。
HTTP 仅接受 localhost、回环地址、RFC1918 IPv4 或 IPv6 ULA 地址，且需手动授权。
其他主机必须 HTTPS 并提供密钥；局域网域名首期请改用明确的私有 IP。
不自动跟随重定向，不绕过证书错误，也不自动重试或切换后端。
明文 HTTP 即使在局域网也不加密，用户需自行确认网络可信。

非秘密配置通过用户级 QSettings 保存，密钥与 HTTP 授权只保留在会话中。
退出后须重新输入密钥、重新授权 HTTP；没有“记住密钥”或自动连接。
服务错误只展示安全错误类别和 HTTP 状态，不记录服务返回的原始错误文本、密钥或请求正文。

## 统计口径

- 连接测试 token 单独累计，包含重新测试，且仅保存于当前会话；不冒充项目/章节用量。
- 连接测试计数不写入项目文件，重启即清零。“重置token计数”须再次点击“确认”，
  才会清零累计输入、输出和用量未知次数；取消或关闭弹窗不改变计数。
  请求进行中禁止重置；重置不影响连接配置、上次响应、小说或服务端统计。
- 服务未提供 usage（包括 null）时显示“未提供”，统计为用量未知，不假装零消耗。
- 失败与取消也可能消耗服务端 token；无法得知时计入未知次数。
- 本阶段为非流式请求，没有精确生成时间和首 token 时间，生成速度明确显示“未提供”。
- 输出 token / 总请求耗时可作为“端到端输出吞吐”，含排队、首包等待等，**不是解码速度**。
- JSON 测试校验短样本为唯一字段 `ok: true`，并要求正常结束；截断或无效输出不标记通过。
- text 模式只验证基础传输与正常完成，不宣称已验证 JSON/schema。

## 第二阶段：原文快照与消息预览

1. 在阅读工作台选择导入的 Markdown 章节，然后切到“小说分析”页。
2. 按服务实际设置填写上下文总上限和预留输出 token；默认值不是服务能力探测结果。
3. 点击“准备当前章快照与预览”，只读取当前章源文件，不调用 API。
4. 查看“原文预览”及“完整消息 JSON”、快照 ID、SHA-256、版本和输入 token 估算。

准备时使用与导入相同的 Markdown 解析器核对全部块及其字节范围；源文件缺失、无效 UTF-8、
正文/标题/偏移变更、路径越出原目录都会阻止准备。单文件安全上限 16 MiB。
采用导入块的首尾范围保存精确 UTF-8 原文，保留 BOM/CRLF 引起的原文件绝对字节偏移。
前置页面元数据不进入发送消息；正文范围内部的原始换行和 Markdown 标记完整保留。
未引用的补充文件、其他章节、源目录绝对路径和 API 密钥不进入消息。
原始章节可能包含个人信息；预览不是自动脱敏器，应由用户检查正文内容。
消息提供块的 UTF-8 `source_start` / `source_end` 范围，配合现有证据 schema；
分析输出只能引用范围，系统从快照提取引用并做确定性证据校验。

快照保存在现有 `.loreforge` SQLite 项目的 `context_snapshots` 中；提示词 v1 和现有
`ChapterAnalyzer` 输出 schema v1 分别写入 `prompt_versions` / `output_schemas`，无需更改数据库版本。
记录项目/书/章 ID、导入 manifest 哈希、当前源文件哈希、章节原文字节哈希、块与来源范围、
完整消息和预算。导入 manifest 哈希是历史记录，不宣称已重新核验整个源目录。
前置页面元数据或末尾空白变化若不影响任何已导入块，可重新准备并记录新的文件哈希。
相同内容和预算复用已有快照；记录不可覆盖，版本冲突或保存失败会回滚整笔事务。
重启后重新准备同一章仍可复用原快照；已发送任务可在分析页历史中查看。

输入量采用本地启发式估算，不是 Qwen tokenizer 的精确计数，也不算实际 token 消耗。
估算超出 `总上限 - 预留输出` 就拒绝准备，不截断正文。
切章、切书、打开失败或修改预算都会清空旧预览；已保存快照仍留在项目中。
快照不包含模型连接配置或请求生命周期，也不等同于 `ContextEngine` 的跨章记忆快照。
发送前必须确认当前章节/源文件、模型与预算，再从保存的内容构建请求。

默认鉴权边界、重定向拒绝、页签切换、阅读布局与旧模块回归；另覆盖精确原文字节、

用户已反馈基础连接和 json_object 短样本通过；开发环境未调用真实工作室 API。
