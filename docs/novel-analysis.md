# 小说分析：单章三角色闭环

## 页面分工

- 阅读工作台：导入 Markdown 源目录、选择书/章、阅读原文。
- LLM 工作台：连接配置、短样本测试、连接测试计数、当前角色用量/响应耗时和小说任务累计。
- 小说分析：章节选择、快照/消息预览、显式发送、结果/证据、复核/审查与任务历史。
- 分割预览：独立的第四个页签，显示分割后的完整小说，对白按说话人染色，叙述与待确认另色显示。

本功能是人物、剧情、地点/设定事实、伏笔/线索的**语义拆解**，不是拆分或重写小说文件。
地点来自已有 locations 契约，设定事实来自 important_facts；本阶段没有独立的全书设定图谱。

## 使用步骤

1. 打开 `.loreforge` 项目，在阅读页选择导入的 Markdown 书；分析页也可直接选择该书章节。
2. 首次在 LLM 页填写模型 ID、完整地址和临时密钥，之后随工程自动恢复。连接测试可选。
   选择服务支持的 `json_object` 或 `json_schema`；text 模式不能启动分析。
3. 在分析页选章，直接开始；预算随工程恢复，可按需调整。可选预览用于提前检查原文和完整消息。
   分析参数、原文/请求预览默认折叠；点击可选预览或结果证据会展开原文区域。
4. 分割小说请点击“独立对白分割”；需要原有剧情/事实/伏笔提取则另点“综合分析（原流程）”。
   “继续…”只续跑所选历史对应的任务；二次“确认”才发送，取消/关闭弹窗不产生请求。
5. 查看三角色状态与结果标签。点击证据条目，可查看由本地快照提取的引用，并按 UTF-8 字节范围定位。
6. 查看当前章历史，或直接开始新任务。每次开始都会重新准备并核验源文件，不使用历史快照直接发送。
7. 切换到右侧第四个“分割预览”页签看分割正文。新版有效历史可直接查看；旧版只有证据的历史需要从头重新分析一次。

## 荧光笔分割预览

### 独立人物与对白任务

“独立对白分割”与原综合分析是不同任务类型，不在同一分析请求里提取剧情、摘要或伏笔。
本地按成对引号和句末/换行组织定位单元 u0001、u0002……，单元只用于定位，不预判说话人。
分析员仅收到一份完整的 source_units 文本和输出契约；返回人物 name/aliases 及 segments 的
first_unit、last_unit、speaker，只列发言/发声，不重抄整章，不计算字节偏移，不为整章分类。
不要求覆盖所有编号，可以跳过标题、叙述、空白、心理和引用词语；没有发声时允许空数组。
本地用不可变编号表恢复原文与字节位置，按原文位置展示；重复“……”靠实际编号区分。
未被提取的文字完整保留为 unassigned（未归属），不自动认定为 narration（旁白），也不因跳号失败。
单条编号无效时记录 extraction_issues，不伪造定位；说话人不在人物表中则保留片段、清空归属。
重叠或跨轮次/叙述边界的范围标为待确认，不任取一个人物；其他有效发声仍可查看。
这些提示写入 normalized_output，原始模型输出不修改。复核员收到本地定位提示；尚有提示时最终状态为需确认，不能靠模型 pass 消除问题。
章节不匹配、快照损坏、无有效 JSON/输出契约、取消、截断与网络错误仍按原规则失败；不自动重试。
成对引号内部可包含多句或嵌套引用，但当前是一个定位单元，不在该单元内部细分多人发言。
未闭合引号不猜测补全，以本地句末单元定位，复杂文本仍可能需要人工核对。
本次专用提示词保留沉默回应、哭声、结巴和未完发言，不把动作/神态或引文词语当对白。
人物标准名归并由本章上下文决定，不要求输出性别、年龄等额外设定，不保证模型语义绝对正确。
复核/审查只检查分割，问题说明须给出定位编号、错误与建议归属，不自动修改或重试。
“人物”结果页按人物列出各次发声，可点选回到原文；不明片段单列“待确认”，预览页继续染色。
历史列表区分 [独立对白] / [综合分析]。复核失败后可续跑对应角色，不重发已完成的分割请求。
两个流程不能互相续接；预算、显式发送确认、SSE、token 累计和历史存储复用既有安全机制。

该页使用本地定位后的 `normalized_output.segments`，不使用人物、事件或别名证据染色。
每段包含原样 `text`、`kind`（dialogue/unassigned/unknown；旧综合结果另有 narration）与 `speaker`。
对白按标准人物名染色；未提取原文不染色；类型不明或对白说话人不明默认琥珀色。
旧综合结果里明确标为 narration 的文字仍显示灰色，与新任务的“未归属”不同。
非对白 speaker 必须为空，已知说话人必须来自人物表。悬停显示归属，可按人物或类型筛选。
完整小说始终来自不可变原文快照；程序将已定位发声与未归属空隙拼成完整展示，保留标题、标点与换行。
不让模型计算偏移、重抄小说或覆盖整章。不再把“模型没有提取某个单元”当作整个任务失败。
此校验保证文本完整性，不保证模型语义正确；复核员和审查员也明确检查对白边界及归属。
本地检查发声范围不能跨成对外层引号边界，把内容与外部叙述或其他轮次混在一起时标为待确认。
支持中文双引号、直角引号、双直角引号与英文双引号，内层引号不强制拆开；未闭合引号不猜测结束位置。
此规则只约束边界，不把引号自动认定为对白：引用词语可以不提取，保持未归属。
预览明确统计对白、叙述、待确认段数（待确认含说话人不明的对白）；人物栏只统计其被归属的对白。
没有识别任何对白时明确警告需人工核对，不再用“人物 0 段”隐去原因。
分析员完成后即可显示候选预览，后续角色未完成、分歧或建议重做时明确标为候选。
只有同流程三角色均 pass 且无本地定位问题才显示流程通过，仍不冒充人工确认或保证无遗漏、准确归属。
独立任务的网络输出不包含整章文本，正文只在本地恢复；原综合流程仍返回完整文本分割。
这减少输出负担，但不承诺真实服务的速度或准确率；预算不足时仍需手动提高，不自动重试。

初始配色按顺序为 #4A2718、#592219、#7A4E47、#CDB0A1、#B98E61、#C7B89C、#DDDDCF、#DBCEC3。
展开“荧光笔设置”可编辑这 8 个 #RRGGBB 色值、不透明度（0–100%，默认 25%）和笔触粗细
（1–40 逻辑像素，默认 14 px）。人物图例右侧可单独编辑颜色，双击人物名可打开选色器，
点击人物名或使用下拉框可只看一个人物。超过 8 人后循环使用配色，可手动调整或单人筛选。

全局配色和显示参数保存在本机应用配置目录 highlight-preview.ini；按书籍 ID 与人物名称的
哈希记忆绑定顺序和单独颜色，不保存小说原文、人物明文名称或 API 信息。配置不随 .loreforge
工程迁移，不升级数据库。当前人物识别仍以分析输出的名称为准，没有新增跨章身份消歧。
打开新版历史时用该历史自身的原文和已校验分割染色；旧历史明确提示无分割，不使用证据冒充。
当前网络 schema v5、提示词 v7；旧 v1/v2/v3/v4 历史仍可只读查看，不能混用续跑。数据库仍为 v7。
旧提示词任务不能续接新流程；已有原始记录不修改。旧结果不满足当前分割边界时明确显示校验错误，需重新开始对应任务。
切章、切书或启动新任务时清除旧高亮，
没有有效结果时只显示未染色文本，不借用其他流程的结果。显示原文使用只读纯文本，不执行 HTML。
染色、筛选、改色和打开此页均不会发送 API 请求，也不修改原文、分析输出或审计记录。

## 从未完成角色继续

“独立对白分割”和“综合分析（原流程）”均创建新的三角色流程，分别使用专用提示词；不会复用其他任务的输出。
在当前章历史选择一条流程，系统按该流程各角色最新请求判断进度：

- 分析员输出有效，复核/审查未完成：显示“继续复核与审查”，最多两次新请求。
- 分析员和复核员输出有效，审查未完成：显示“继续审查”，最多一次新请求。
- 分析员未完成，或三角色全部完成（包括审查建议重做）：不显示继续按钮。

继续仍需一次确认，列明复用的角色、将运行的角色、当前接口与模型；取消不发送。
源文件/导入来源/章节、前序 JSON 契约及证据会重新校验；不能混用不同流程的结果。
接口、模型、思考模式、响应格式、输出参数字段变化时拒绝直接复用；超时、输入/输出预算可调整，临时 Key 可轮换。
早期任务未记录接口地址，无法事后验证旧地址。确认框会单独提示并要求明确使用当前接口，不冒充已核验。
异常中断留下的远端任务可能仍在运行，继续会产生新消耗。不会自动续跑或自动重试。

继续沿用原 pipeline ID，但每次操作有独立 execution ID、新请求与新结果记录，记录复用的 run ID。
失败/取消/中断记录与原有效结果均不覆盖，复用本身不新增 token 消耗；累计包含实际新请求和之前失败的已知/未知用量。
请求序号确保多次继续后优先显示每个角色最新尝试，避免旧失败覆盖新成功；打开工程后也可选择历史继续。

角色表“输出校验通过”只说明结构/证据符合契约；最终“审查建议重做”是模型内容意见，不是程序执行失败。
最终状态直接显示意见原因，完整原因与原文证据在“复核 / 审查”标签；不会因建议而自动重跑。

发送确认授权本章的至多三次串行请求：分析员接收原文，复核员接收原文和已校验分析，
审查员接收原文、分析和复核意见。角色输出是不可信模型数据，不作为系统指令。
没有批量发送、自动重试、自动修编、自动写入故事记忆或自动续跑。
三个角色始终使用同一个冻结的连接/model ID；角色独立提示词**不是独立模型验证**。
任务进行中锁定 LLM 配置和连接测试；切换阅读章节/项目或关闭窗口会取消当前任务。
取消并不保证远端停止计算，也不保证没有 token 消耗。

## 全局任务状态灯

窗口左下角显示任务灯、当前任务/角色和运行耗时，原有章节/字数等状态信息位于其右侧；切换页面后任务灯仍可见。
蓝色表示本地处理，青色表示等待模型响应，运行时默认三秒一个呼吸周期；
可在 View 菜单关闭“任务灯呼吸动画”。绿色表示成功，四秒后恢复灰色就绪；
黄色表示需重做或待人工确认，红色表示失败，取消则为灰色并保留取消文字。
点击红灯可确认提示并恢复灰色就绪，不重试、不删除日志、结果、历史或 token 统计。
新任务开始也会更新状态；旧任务结束不会覆盖更晚启动的活动任务。
任务灯只是本会话提示，不是持久化审计；具体错误仍在原功能页面查看。
等待响应不代表能判断远端正在生成或卡住；不显示虚构进度。
导入与预览目前是同步本地操作，开始时刷新状态，处理期间动画/耗时刷新可能暂停。

## 校验与结论

每角色发送前及响应后重新读取核验当前章源文件；原文或快照发生变化则停止，不把过时结果写成成功。
模型只返回结构化证据范围，本地从固定 UTF-8 快照提取引用。越界、UTF-8 字符断裂、串章、
无证据直接断言、无效置信度、重复名字、schema 不符合、未正常结束/截断均会阻止继续。
重复原文引用按字节位置映射，不能仅靠字符串搜索定位第一处相同文字。

复核/审查返回 `pass` / `redo` / `human` 和证据问题；pass 必须无问题，其他结论须提供非空原因和有效本章证据。

- 审查员要求 redo：审查建议重做（模型意见，非程序失败），显示原因，不自动重跑。
- 复核与审查均 pass，且本地结构/证据校验均通过：通过（同模型角色检查，非独立验证）。
- 其他完整有效组合，包括复核不通过而审查通过：待人工确认。
- 任一请求、结构/证据、来源或保存失败：任务停止；此前有效分析仅为候选，不是最终通过。

结构与范围正确不能证明模型理解正确。置信度是模型自报，不是校准后的准确率。
本阶段“人工确认”是结论提示，尚无人工签核落库按钮。

## 持久化与统计

分析审计沿用原有结构；工程 API 设置新增 schema v7 自动迁移，旧版程序不再支持打开 v7 工程：

- `llm_runs`：每个角色的请求 UUID、状态、模型、耗时、服务报告的输入/输出/总 token 和安全错误。
- `llm_run_artifacts`：精确无鉴权头 JSON 请求体、正常响应（移除标准思考字段）、解析输出及 schema 校验报告。
- `context_snapshots`：角色消息、来源快照 ID、pipeline ID、预算、冻结 model 和独立的结果回执。
- `prompt_versions` / `output_schemas`：不可覆盖的分析、复核、审查提示词和契约版本。

请求记录和角色快照在真正发送前保存；结果及状态通过事务一起保存，保存失败不能标记成功。
领域校验诊断单独保存在结果回执和 run 错误中；schema 报告仅表示 schema 校验，不冒充领域校验。
API Key 按用户选择明文保存于 project_api_settings，仅用于鉴权头，不写入请求体、分析快照或日志；
HTTP/网络错误正文不落库，反射凭据的正常响应也拒绝保存与显示。
响应解析失败时只保存安全诊断：固定分类、白名单结束原因、正文/思考 UTF-8 字节长度、
JSON 错误偏移以及有效的服务端 token 用量。不会保存失败响应正文或思考正文。
结束原因不识别则记录 other，缺失记 missing；长度/偏移 -1 表示未提供。
诊断位于结果回执 response_diagnostics，旧记录不回填，也不自动重发小说。
合法完整 usage 即使伴随空正文/截断/解析失败也计入已知累计；格式异常或缺失则仍计未知。
length 是服务报告的长度限制，不能仅据此判定一定是思考耗尽了预算；不猜测中转站行为。
新保存的正常响应会移除 message 中 reasoning_content/reasoning/thinking/reasoning_details 字段；
保留最终正文和用量，历史已存在的数据不改写。
小说和正常结果会保存在本地项目中，项目文件并未加密，请按含原文的资料管理，不提交到 GitHub。

项目/本章累计包含三角色、重复运行和失败中可知的消耗，不包含连接测试。
缺失 usage、取消、超时、失败或未完成任务的未知消耗单独计数，不把未知标成零消耗。
实际输入/输出 token 在角色记录中保存；界面累计展示服务报告 total_tokens。
连接测试的“重置token计数”只清本会话连接测试累计，**不删除项目中的任务审计和累计**。
此版本使用 SSE，显示响应耗时；生成速度没有精确数据，明确显示未提供。

正常完成、失败、取消的记录重启后可查看。程序异常中断留下的 running/pending 状态显示未完成/可能中断，
不显示成功、不自动续跑；用户检查历史后可明确继续未完成角色，或从头重新分析。
每个角色加入前序输出后独立检查启发式预算，超限会停止，不静默截断或移除证据。

## 验证范围与后续

三角色提示词 v3 保留原有别名规则，区分固定别名、自称、临时称谓与亲属指代。别名证据必须支持名称和人物的
对应关系，不能只证明词语出现；复核员与审查员逐项检查此语义，发现误归类给出 redo 和证据，
无法判断给 human。不使用“老子”等全局禁词，以保留历史人物、明确命名及真实绰号。
此规则是模型提示约束，不是确定性的自然语言判别器，也不保证模型不再误判。
旧提示词和分析历史保持不变；旧提示词/字节证据结果不能续接为新编号流程，需重新开始对应任务。
段落编号证据自网络 schema v2 引入，v3 增加完整正文分割，v4 引入独立对白编号契约，当前 v5 改为只提取发声、不要求全覆盖；字节证据领域 schema 仍为 v1；数据库仍为 v7，无需数据迁移。

## 段落编号证据

准备章节时为每个原文块（含标题、段落等）分配章内稳定编号 b0001、b0002……，
在不可变快照 blocks 中保存编号到原始 UTF-8 字节范围的映射。消息 source_blocks 提供编号及原始块文本，
source 中仍保留完整原文，不改写源文件、不截断正文；段落表会增加输入量，仍逐角色检查预算。
编号只在当前章快照中有效，不是跨章人物或全书段落 ID。

分析员 evidence 每项为 `{"block_id":"b0002"}`；复核/审查 issues 每项为
`{"reason":"问题说明","block_id":"b0002"}`。模型不再返回 source_start/source_end。
后续角色接收的 analysis/checker 仍是原始编号输出，不回传换算后的字节证据诱导模型计算偏移。
映射器检查编号、重复引用、范围与 UTF-8 边界，把整段证据换算成已有领域契约后继续严格校验。
无效编号、未知编号、旧字节字段均拒绝，不跳过、不模糊匹配，不调整边界，也不改 inferred 来绕过错误。

llm_run_artifacts 的 parsed_response 及正常响应仍保留模型原始编号输出，schema 报告仅校验网络契约。
独立回执中 normalized_output 保存本地换算结果，normalization_format 为 loreforge-block-evidence-resolved-v1；
领域错误仍单独记录。正文无法换算时不保存部分换算结果，但保留原始回答供诊断。
重开历史、继续任务与阅读证据定位均从历史自身的不可变映射重新换算，不依赖当前源文件做模糊搜索。
旧 schema v1 的字节证据历史继续只读显示；旧契约继续按钮隐藏，控制器也拒绝混用。
结构与范围校验只证明引用可定位，不保证结论或别名语义正确，仍需复核与审查。

回归测试使用本地模拟 HTTP 服务和原创 Markdown，包括三角色串行、精确请求审计、未知用量、
取消/快速重启/超时、异常关闭、无重试、源文件变更、篡改快照、截断、串章、UTF-8 证据、
复核分歧、预算溢出、凭据反射拒绝、发送确认、页签分工、历史恢复和重复引文精确定位。
真实工作室模型的单章能力尚未由开发环境验证，应由用户在 GUI 主动发送并检查结果。
后续可增加人工签核、跨章记忆与一致性检查、批量队列、证据引文辅助映射和流式性能统计。

## SSE 接收与当前请求消息框

HTTP POST 仍一次发送完整 JSON 请求；响应改为 `text/event-stream`，不是将小说分成多次 API 请求。
连接测试及三个分析角色均使用 `stream: true` 和 `stream_options.include_usage: true`，无自动重试、
无流式失败后的自动重发。服务不支持这些参数时需检查服务配置；不会静默换一种方式再次发送小说。
服务若忽略 stream 而直接返回普通 JSON，仍按原规则完整校验，并明确显示“非 SSE”。

窗口底部只读小框展示本次请求已接收的正文和字节统计，每次新请求（包括切换角色）清空；
结束或取消后保留这一请求的显示，旧请求迟到事件不会覆盖新请求。不回放历史 SSE。
正文实时预览是未确认输出，不代表分析结论；思考正文不显示、不保存，仅统计 UTF-8 字节数。
显示节流为 100 ms、最多展示正文末尾 32768 字符，完整正文仍用于最终校验；已知凭据跨片段反射也隐藏。
收到正文或 reasoning_content 增量时，左下角显示“[分析中]”；只有心跳/控制事件则显示连接活跃。
连续 5 秒无事件改为等待后续数据，不直接判失败。配置的超时仍是整次请求总时限，心跳不会无限延长。

按 SSE 空行重组事件，支持 UTF-8 拆包、CR/LF/CRLF、注释心跳、多行 data 和独立 usage 尾包。
必须收到 finish_reason 和 `[DONE]`，并通过既有 JSON/schema/领域/证据校验才算完成。
缺失结束标记、截断、错误事件、工具调用或异常事件格式均不作为成功结果。
单次响应上限 16 MiB、单事件上限 1 MiB，超限安全停止。
成功审计保存精确请求及由 SSE 拼合的标准响应 JSON，不把重建 JSON 冒充原始 SSE 帧；
思考文本不进入重建响应。失败只保存安全诊断，合法尾包 usage 按一次请求计数，缺失则未知。
数据库版本不变，既有非流式历史仍可查看；满足原续跑条件的同版本角色结果仍可复用。

兼容层允许无调用含义的空占位：`tool_calls: null/[]`、`function_call: null/{}`、
`error: null`、空 choices 的控制/usage 事件、单候选省略 index，以及带明确非空
finish_reason 的空/缺失 delta。空 finish_reason 仅表示未结束，仍必须等到明确结束和 `[DONE]`。
非空工具调用、错误载荷、非零/异常 index、多候选、正文类型错误和重复结束仍拒绝。
这些规则不证明某个真实中转站采用了其中哪种格式，需要根据实际失败诊断判断。

SSE 失败诊断新增固定枚举 `stream_problem`、事件序号 `stream_event_index` 与事件字节长度
`stream_event_bytes`，不保存事件原文、任意服务端字段名或思考正文。事件 JSON 解析失败时，
json_error_offset 指向当前 data 事件内部。已确认收到 SSE 的失败回执标记 response_transport=sse；
未保存正常响应时 response_record_format=none，不再把已识别 SSE 的协议失败写成未知传输。
